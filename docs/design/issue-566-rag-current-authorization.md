# 저장 답변·RAG 문맥의 현재 문서 권한

관련 이슈: #566. 권한 회수 후 시작하는 새 조회와 모델 입력 준비에 현재 Primary의 문서 읽기 권한을 적용한다.

## 정책

- 저장 검색 발췌는 현재 읽을 수 있는 문서만 반환한다.
- 답변은 직접 근거와 사용한 이전 답변의 전이적 출처를 함께 기록한다. 한 출처라도 금지되면 답변 전체·인용을 재검색 안내로 대체한다. 문자열 일부를 제거해 안전하다고 추정하지 않는다.
- 출처 기록이 없는 이전 답변은 내용·인용·후속 문맥에 사용하지 않는다. 원본 DB 행을 삭제하지 않으며 사용자 자신의 질문과 허용된 발췌는 유지한다.
- 모델 직전에는 현재 허용된 검색 결과·이전 문맥으로 프롬프트를 재구성한다. 모델 응답 확정 전 출처를 다시 검사해 회수된 답변을 저장하지 않는다.

## 구현 경계

`rag_responses.source_document_ids_json`에 모든 문서 출처를 기록한다. NULL은 추적 불명, `[]`는 문서 근거 없는 고정 응답이다. 새 컬럼은 nullable로 추가하며 불확실한 기존 데이터를 임의 역산해 채우지 않는다.

`RagDocumentAccessService`가 문서별 Primary 인가를 하나의 호출 단위로 모으고 출처 JSON을 엄격하게 해석한다. 조회 서비스는 발췌·인용·답변을 이 판정으로 조립한다. `RagPromptPreparationService`는 짧은 트랜잭션에서 후보와 과거 문맥을 준비하고 DTO로 반환한다. 모델 호출 동안에는 DB 트랜잭션을 유지하지 않는다.

프롬프트·출처 갱신도 PROCESSING·token 일치·lease 유효 조건을 통과해야 한다. 완료는 기존 조건부 갱신을 유지한다. 성공 답변의 인용은 실제 모델에 보낸 후보와 동일하게 저장한다.

## 동시성·한계

Primary 인가는 짧은 DB 트랜잭션의 확인 시점을 기준으로 한다. 외부 HTTP 전달과 권한 회수 커밋을 하나의 원자 연산으로 묶지 않으며 이미 전송한 입력을 회수한다고 주장하지 않는다. 모델 처리 중 회수는 저장 전 재검사와 조회 시 재인가로 차단한다. 권한 DB 조회 오류는 허용으로 추정하지 않는다.

전이적 출처가 늘면 인가할 고유 문서 수도 늘어난다. 같은 조회 안에서는 중복 문서를 한 번만 검사하지만 대규모 이력의 인가 비용을 새 성능 성과로 주장하지 않는다.

## 검증

이전 로컬 HTTP 재현의 완료 답변·대화, 접수 대기 프롬프트, 후속 답변 문맥을 같은 조건으로 재검증한다. 추가로 모델 처리 중 회수·출처 누락/손상·전이적 출처·다른 사용자 소유권·허용 문서 보존과 token 경합을 확인한다. 실행 증거는 `docs/test-results/`에 보존한다. 공개 설정·개인 환경 파일은 변경하지 않는다.
