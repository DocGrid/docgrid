# RAG 답변이 중국어 전환 지점에서 단어 중간에 잘리는 문제 수정 (#508)

closes #508

#502 README 빠른 실행 재현 중 관찰한 "RAG 답변 문장 중간 잘림 + 생략 안내"(#502 설계 문서 4.4절)의 원인을
찾아 고친다.

## 1. 배경

2026-10-15 새 PC 재현(로컬 `qwen2.5:7b` Native, 100% GPU)에서 아래 질문의 답변이 잘렸다.

- 질문: "오로라 프로젝트에서 원격 근무는 일주일에 며칠까지 가능하고 장비 지원금은 얼마야?"
- `rag_responses`: `status=SUCCESS`, `input_token_count=543`, `output_token_count=291`, `latency_ms=13452`
- 답변(148자): "오로라 프로젝트에서는 구성원이 일주일에 최대 3일까지 원격 근무를 할 수 있으며, 원격 근무자는
  연 1회 모니터와 의자 구입 비용으로 최대 45만 원의 장비 지원금을 받" + "(※ 답변이 길어 일부 내용이
  생략됐을 수 있습니다. 자세한 내용은 문서를 확인해주세요.)"

출력 291 Token은 `ollama.num-predict` 400보다 작고 13초는 `generate-deadline` 60초보다 짧다. 291 Token에
비해 남은 한국어가 한 문장뿐이라 생성된 대부분이 후처리에서 버려졌다는 뜻이다.

### 1.1 잘림 안내가 붙는 조건

`OllamaClient.generateAnswer()`는 세 조건 중 하나라도 해당하면 문장 경계로 트리밍하고 안내를 붙인다.

| 조건 | 이번 사례 |
|------|-----------|
| 토큰 상한 도달 (`eval_count >= num_predict`) | 아님 (291 < 400) |
| 조기 종료 (`done` 없이 스트림 종료: 데드라인 초과, PEG 파서 취소) | 아님 (`eval_count`는 `done:true` 마지막 청크에만 온다) |
| 한자·가나 대량 혼입 컷 (`sanitizeAnswer()`, 8자 초과 시 첫 혼입 지점에서 자름) | **해당** |

### 1.2 재현

VM DB에 저장된 `prompt_text`를 `OllamaClient`와 같은 요청 본문(`raw:true`, `stream:true`, `num_predict`
400, `temperature` 0.3, `top_p` 0.8, `repeat_penalty` 1.1, `repeat_last_n` 256)으로 Native Ollama 0.40.4에
다시 보냈다.

| 방식 | 횟수 | 대량 혼입 | 비고 |
|------|------|-----------|------|
| 저장된 프롬프트 그대로 | 10 | 2 | 2회 모두 "받" 다음 "可以获得…"로 전환. 저장된 답변과 앞부분이 글자 단위로 같다 |
| ChatML 템플릿 직접 적용 | 20 | 2 | 같은 지점("받")에서 전환. 템플릿은 원인이 아니다 |
| 잘린 지점("…지원금을 받")부터 이어 쓰기 | 20 | 6 | 같은 토큰에서 다시 전환 |

모델이 "을 수 있습니다"를 쓸 자리에서 같은 뜻의 "可以"를 고르며 중국어로 넘어간다. 혼입이 8자를 넘어
첫 혼입 지점("받" 바로 뒤)에서 잘리고, 답변이 한 문장이라 `trimToSentenceBoundary()`가 되돌아갈 마침표를
찾지 못해 원문을 그대로 돌려준다. 그래서 단어 중간에서 끊긴 채 "답변이 길어" 안내가 붙었다.

## 2. 결정

대량 혼입 컷이 나면 **같은 데드라인 안에서 한 번 새로 생성**하고, 재생성 답변이 잘림 없이 끝났을 때만
그것을 쓴다.

- 데드라인은 첫 요청 시작 시각 기준 하나를 공유한다. 첫 요청이 데드라인을 넘겼으면 재생성하지 않는다.
  전체 생성 시간이 `generate-deadline`(60초)을 넘지 않으므로 `rag.worker.stale-threshold`(90초)와도
  충돌하지 않는다.
- 재생성 답변도 혼입·토큰 상한·조기 종료로 잘렸거나, 요청이 실패(답변 없음, 서버 오류)하면 첫 답변을
  기존 방식대로 잘라 안내를 붙인다. 재생성 때문에 기존보다 나빠지는 경우는 없다.
- 반환하는 `inputTokenCount`·`outputTokenCount`는 실제로 쓴 답변의 값이고, `latencyMs`는 재생성을 포함한
  전체 시간이다.
- 재생성 여부와 사용 여부는 `log.warn`으로 남겨 빈도를 추적한다.

### 대안과 선택 이유

| 대안 | 판단 |
|------|------|
| 잘린 지점부터 이어 쓰기 | Token은 덜 쓰지만 전환이 일어난 바로 그 토큰에서 다시 시작해 재전환 확률이 30%(6/20)로 새로 생성(20%)보다 높다 |
| 안내 문구·트리밍만 정리 | 코드는 가장 작지만 "…받"처럼 내용이 잘린 답변은 그대로라 문제를 해결하지 못한다 |
| ChatML 템플릿 적용 | 혼입률이 줄지 않았다(2/20). 꼬리 반복은 줄지만 별개 문제다 |
| 로짓 바이어스로 한자 Token 금지 | Ollama `/api/generate` 옵션에 없다 |

## 3. 비목표

- raw 모드에서 한국어 답변 뒤에 "Translation in Korean: …" 반복이나 "관련 문서를 찾지 못했습니다." 꼬리가
  붙는 현상. ChatML 템플릿을 직접 적용하면 20회 중 16회가 한국어 답변만으로 끝났지만, 모델을 바꾸면
  템플릿도 달라져야 해서 별도 이슈로 다룬다.
- 토큰 상한·조기 종료 잘림의 재생성. 이번 원인과 무관하다.
- 혼입 임계값(8자)·안내 문구 변경.

## 4. API 명세

외부 API·응답 형식 변경은 없다. `POST /search`가 접수한 비동기 RAG Job의 `answer` 내용만 달라진다.

| 상황 | 변경 전 | 변경 후 |
|------|---------|---------|
| 첫 생성이 대량 혼입 컷, 재생성은 정상 | 첫 답변 잘림 + 안내 | 재생성 답변, 안내 없음 |
| 첫 생성·재생성 모두 대량 혼입 컷 | 첫 답변 잘림 + 안내 | 같음 (첫 답변 잘림 + 안내) |
| 첫 생성 대량 혼입 컷, 재생성 실패 | 첫 답변 잘림 + 안내 | 같음 |
| 첫 생성이 대량 혼입 컷이면서 데드라인 초과 | 첫 답변 잘림 + 안내 | 같음 (재생성하지 않음) |
| 첫 생성부터 답변 없음·서버 오류 | `RAG_SERVICE_UNAVAILABLE` → extractive fallback | 같음 |

## 5. 검증

### 5.1 단위 테스트

`OllamaClientTest`에 4건 추가.

- 단어 중간 혼입 컷("…지원금을 받可以获得…") 후 재생성 정상 → 재생성 답변을 안내 없이 반환, 호출 2회
- 재생성도 대량 혼입 → 첫 답변을 잘라 안내 부착, 첫 답변의 Token 수 유지
- 재생성 응답 없음 → 첫 답변을 잘라 안내 부착
- 데드라인 경과 후 혼입 컷 → 재생성하지 않음(호출 1회)

`OllamaClientTest` 19건(기존 15 + 신규 4) 통과. RAG 도메인 테스트 86건(Repository·통합 테스트 포함)도 모두
통과했다.

`./backend/gradlew -p backend test`(일회용 `JWT_SECRET` 주입) 전체 결과는 1412건 중 49건 실패였다. 실패는 모두
OllamaClient와 무관한 통합 테스트였고, 원인은 로컬 PostgreSQL 연결 한도 초과
(`FATAL: sorry, too many clients already`, 18건)와 STOMP `ConnectionLostException`(20건) 등 실행 환경이었다.

### 5.2 실제 Ollama 재현

변경된 `OllamaClient`를 운영 설정과 같은 값(`qwen2.5:7b`, `num_predict` 400, 데드라인 60초)으로 만들어
저장된 프롬프트를 Native Ollama에 15회 보냈다(커밋하지 않은 임시 하네스).

| 결과 | 횟수 | 비고 |
|------|------|------|
| 정상 종료, 안내 없음 | 10 | 4.8~7.8초 |
| 대량 혼입 컷 → 재생성 답변 사용, 안내 없음 | 2 | 15.4초, 22.7초 (혼입 85자, 316자) |
| 토큰 상한 400 도달, 안내 부착 | 3 | 한국어 답변이 끝난 뒤 번역·반복 꼬리가 400 Token을 채움 |

토큰 상한 3건은 모두 꼬리에 "관련 문서를 찾지 못했습니다"가 있어 `RagFacade`가 그 지점부터 잘라내므로 안내가
최종 답변에 남지 않는다. `RagFacade` 처리까지 적용하면 15건 모두 안내 없이 완결 문장으로 끝났다. 다만
"(번역 없음)", "(답변 완료)", 영어 번역 같은 꼬리는 남는다(3. 비목표).
