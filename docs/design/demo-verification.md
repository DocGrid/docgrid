# 예제 시연 검증과 실행 원장

## 목적과 경계

예제 15건이 INDEXED여도 검색 HTTP 오류나 빈 결과를 성공으로 종료하던 판정을 수정한다.
기존 인증·멱등 업로드·인덱싱 대기는 재사용하며, 생성 모델의 품질 평가나 OpenSQL HA 검증은 포함하지 않는다.

## 판정

| 단계 | search 필수 | rag 필수 | 통과 기준 |
| --- | --- | --- | --- |
| 업로드 | 예 | 예 | 서로 다른 문서 ID 15건 |
| 인덱싱 | 예 | 예 | INDEXED 15건 |
| 검색 | 예 | 예 | 고정 질문 3개에서 기대 문서가 topK 3 안에 포함, DOCX 표 본문 확인 |
| 원본 | 예 | 예 | 파일 API 바이트 15건의 길이·SHA-256 일치 |
| 생성 답변 | 아니오 | 예 | SUCCESS·비어 있지 않은 답변·검색 후보 문서/Chunk에 속한 인용 |
| 재실행 | 이전 원장 지정 시 | 이전 원장 지정 시 | 같은 대상·계정·예제 fingerprint와 문서 ID 일치 |

PASS/FAIL/NOT_RUN을 구분하며 필수 단계가 NOT_RUN이어도 성공 종료하지 않는다.
search 범위는 RAG 검증을 생략하는 것이며 백엔드 RAG Worker를 비활성화하지 않는다.
`--query`를 지정하면 고정 기대 문서 검증 대신 사용자 질문 1건의 비어 있지 않은 결과만 검사한다.
따라서 이 경우 고정 검색 3/3 통과를 주장하지 않는다.

## 실행 순서

```text
예제 파일·checks.json 고정
  → 임베딩 준비 확인
  → 기존 계정 준비·파일 해시 키 업로드
  → INDEXED 대기
  → 기대 검색·본문 + 파일 API 해시 대조
  → 선택 RAG / 선택 이전 문서 ID 비교
  → 필수 단계 전체 PASS일 때만 종료 코드 0
```

## 원장과 민감정보

- 실행마다 `.demo/reports/<run-id>/`를 새로 만든다. 지정한 결과 디렉터리가 이미 있으면 거부한다.
- `events.jsonl`은 안전한 상태 이벤트를 즉시 flush하고 `summary.json`은 최종 판정·건수·시간·문서 ID를 보관한다.
- 예제·검증 질문 fingerprint, 소스 revision, topK와 실행 범위를 남긴다. 실제 모델 revision은 이 원장만으로 증명하지 않는다.
- 대상 주소·계정은 원문 대신 비교용 fingerprint를 사용한다. 원장은 기본적으로 로컬 Git 제외 경로에 둔다.
- 비밀번호·토큰·이메일·서버 URL은 출력 전에 제거한다. 검색 원문·모델 답변·서버 임의 오류 본문을 기록하지 않는다.
- 문서 ID 재사용은 해당 API 결과 비교이며, 이 검사만으로 DB 내부 Job 중복 0을 주장하지 않는다.
