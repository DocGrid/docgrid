# DR-BACKUP-SETUP-20261015-R1 — 비공개 백업 수신 경로

- 목적·성공 기준: 외부 IP 없는 전용 백업 VM에서 기준 백업과 연속 WAL을 받을 수 있고, 설치용 NAT는 제거되어야 한다.
- 위치·절차: GCP 전용 서브넷·VM·서비스 계정·비공개 버킷 구성, IAP 접속, Barman 3.20.1과 PostgreSQL 17 클라이언트 설치, Primary의 백업 역할·접속 규칙·복제 슬롯 설정.
- 시각: 2026-10-15 KST. 자원 생성 단계별 정확한 시작·종료 시각은 별도로 캡처하지 않았다.
- 실행 결과: 최초 서브넷 안은 주소 대역 충돌로 실패, 다음 VM 안은 SSD 할당량 제약으로 실패했다. 전용 서브넷·e2-small 표준 디스크 구성에서 외부 IP 0개로 생성했다. 설치 중에만 임시 NAT를 사용하고 제거했다. Barman 설정에서 물리 슬롯 이름 누락을 수정한 뒤 `barman check`의 streaming 항목이 통과했다. `max_slot_wal_keep_size=4GB`를 설정했다.
- 관측·판정: 전용 VM과 독립 버킷을 확보했고, 사후 점검에서 WAL 수신 프로세스 1개, 활성·`reserved` 슬롯, 임시 NAT 없음. **통과.** Barman 수신기는 현재 Primary 대상이며 자동 failover 재설정은 미검증이다.
- 보안·정리: 공개 문서에 실제 프로젝트·호스트·버킷·주소·계정 이름을 기록하지 않았다. 임시 OS Login 키는 세션 종료 때 제거 명령을 실행했다. 프로필의 기존 키와 구별되는 식별자가 없어 독립적인 잔여 0건 판정은 하지 않았다.
