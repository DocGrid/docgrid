# DR-BASEBACKUP-20261015-R1 — OpenSQL 기준 백업

- 목적·성공 기준: 운영 OpenSQL의 물리 기준 백업을 수집하고 manifest와 별도 파일 복원으로 읽을 수 있어야 한다.
- 위치·절차: 비공개 백업 VM의 Barman `backup`, `verify-backup`, `restore`; 기준 백업 카탈로그를 비공개 GCS 보존 위치에도 압축 보관.
- 시각: 기준 백업 2026-10-15 02:54:15~02:54:20 KST, 보존 압축본 03:03:24~03:03:49 KST.
- 관측: 기준 백업 약 150,901,130바이트. `verify-backup` 통과. 파일 복원 1,899개·약 150,861,383바이트. 압축 보존본 19,123,652바이트를 다시 받아 SHA-256을 일치시켰다.
- 실패·재시도: 복원 파일의 권한 때문에 일반 사용자 `PG_VERSION` 조회가 false로 나왔다. `sudo test`로 재확인했고 파일이 존재했다. 최초 상태 출력 파서는 백업 상태를 잘못 읽었으나 실제 `verify-backup`과 파일 복원은 통과했다.
- 판정: **기준 백업 수집·파일 복원 통과.** 이 기록 단독으로 시점 복원 성공을 주장하지 않는다. 임시 복원 디렉터리는 후속 정리에서 삭제했고 Barman 카탈로그와 비공개 압축본은 보존했다.
