# 외부 보존본에서 미완료 인덱싱 Job 재개 시험 계획

## 실행 경계

- 실행 ID 접두사: `DR-JOB-OFFSITE-20261017`. 서로 다른 목적과 재시도는 별도 파일·번호로 기록한다.
- 기준 리비전: `develop`의 PR #530 병합 커밋. 시험용 OpenSQL 클러스터와 비공개 GCS 원본 보존본만 사용한다.
- 원본 DB와 GCS의 기존 사용자 데이터는 수정하지 않는다. 시험 계정·문서·Job에는 고유 식별자를 사용한다. 시험용 원본이 30일 최소 보존 버킷에 복사되면 즉시 삭제할 수 없음을 기록한다.
- 원래 Standby 한 대에서 격리 복원이 필요하다면 원복 타이머를 먼저 설치·실제로 검증하고, 시험 중 클러스터가 리더 1·Standby 1로 낮아지는 시간을 제한한다. 모델·Worker·격리 GCS 경로가 준비되지 않으면 장애 주입을 시작하지 않는다.
- 비공개 VM 이름·주소·프로젝트 ID·버킷·키·계정·토큰·원문은 원시 로그에 기록하지 않는다. CLI 결과는 프로세스 메모리에서 비식별 집계로만 바꾸어 기록한다.

## 합격 기준과 주장 범위

1. **복원 전 씨앗**: 합성 PDF 또는 DOCX의 업로드가 성공하고, 해당 버전의 Job이 Worker에 의해 실제로 `PROCESSING`과 Attempt 시작 상태가 된 뒤 Worker를 중단한다. GCS 보존 사본의 크기·SHA-256과 목표 시점까지의 완료 WAL을 확인한다.
2. **외부 입력으로 격리 복원**: 외부 완료 기준 백업·WAL만 사용해 중단된 Job 기록을 포함한 목표 시점으로 복원한다. 복원 DB의 시험 버전·Job·Attempt와 GCS 원본을 대조한다.
3. **재개**: 격리 Worker가 Lease 만료 후 Job을 재획득해 `INDEXED`까지 처리한다. 시험 버전의 최종 Job·청크·활성 임베딩 중복은 0건이며, 실제 API 검색에서 해당 문서 근거를 받는다. 실제 모델을 사용할 수 없으면 스텁 조건을 명시하고 의미 검색 품질을 주장하지 않는다.
4. **새 쓰기와 원복**: 복원된 서비스에서 별도의 새 합성 문서 업로드를 확인한다. 시험 종료 후 격리 프로세스·포트·임시 권한·키를 정리하고 원래 DB 리더 1·streaming Standby 2 및 Barman WAL 수신을 확인한다. 최소 보존 중인 합성 사본은 예외로 남긴다.

복원 뒤에만 업로드하거나 단순히 `PENDING` Job을 처음 처리한 결과는 **중단된 Job의 복구**로 판정하지 않는다. 성공 응답 원장 전체를 대조하지 않으면 RPO 0을 주장하지 않고, 준비·재시도 시간이 섞인 경과 시간을 단일 RTO로 표시하지 않는다.
