# OpenSQL 3노드 라이선스 배치 검증 — 2026-09-23

## 범위와 결과

Google Cloud의 Rocky Linux 9.7 (Blue Onyx) `x86_64` 컨테이너 3개에 각각 발급된 체험판 라이선스를 영속 볼륨에 배치하고, 실행 중인 컨테이너 안에서 파일을 확인했다. 이 단계에서는 **OpenSQL DBMS를 아직 설치하지 않았으므로 라이선스의 런타임 활성화를 검증한 것이 아니다.** 이후 설치·실행 결과는 [3노드 실행 검증](gimin-opensql-three-node-runtime-activation-20260923.md)에 별도로 기록했다.

공개 문서에는 프로젝트 ID, 실제 호스트명·사설 IP, 파일의 절대 경로, 라이선스 원본과 해시를 포함하지 않는다. 이 값들은 각 노드에 설치할 라이선스가 서로 뒤바뀌지 않았는지 비공개 환경에서 대조하는 데만 사용했다.

## 배치 확인

| 논리 노드 | 확인 결과 |
|---|---|
| node1 | 해당 노드용 라이선스가 컨테이너의 영속 볼륨에 존재함 |
| node2 | 해당 노드용 라이선스가 컨테이너의 영속 볼륨에 존재함 |
| node3 | 해당 노드용 라이선스가 컨테이너의 영속 볼륨에 존재함 |

세 파일 모두 설치 전 파싱에 성공했고, 각 파일의 호스트 바인딩 값이 대상 컨테이너의 실제 호스트명과 일치했다. 발급된 라이선스는 OpenSQL Enterprise 체험판이며 CPU 제한은 노드당 논리 CPU 2개다. 배치 직후 파일 소유자·권한은 `root:root`, `0644`였으며, DBMS 설치 후에는 실행 계정이 읽을 수 있도록 `opensql:opensql`, `0640`으로 조정했다.

## 실행 환경 대조

세 컨테이너 모두 Rocky Linux 9.7 `x86_64`에서 실행됐고, `lscpu`는 논리 CPU 2개, 소켓 1개, 소켓당 코어 1개, 코어당 스레드 2개를 표시했다. 메모리 제한은 컨테이너당 6 GiB, 재시작 정책은 `unless-stopped`였다. 따라서 표시된 토폴로지는 `1 소켓 × 1 코어/소켓 × 2 스레드/코어 = 논리 CPU 2개`이며 발급된 CPU 제한과 일치했다.

이 단계의 검증 범위는 **파일 배치·메타데이터·호스트 바인딩·CPU 토폴로지**까지다. DBMS 프로세스의 라이선스 경로 전달, 모듈 로드 및 SQL 실행은 후속 실행 검증에서 확인했다.
