# Barman WAL 수신 대상 전환 준비 기록

## 범위

2026-10-16 KST에 분리 작업 트리와 GCP 백업 VM에서 **리더 식별 경로와 감시기 읽기 전용 동작**을 확인했다. Barman 모델 전환, DB 역할 변경, 새 timeline의 WAL 연속성, 복원 가능 시점은 이 기록에서 시험하지 않았다. Barman이 자동으로 새 Primary를 따라간다고 아직 주장하지 않는다.

백업 VM은 외부 IP 없이 유지했고, DB의 기존 Patroni 관리 포트는 열지 않았다. 백업 VM의 단일 내부 주소에서 DB 3노드의 지표 전용 TCP 18008로 가는 허용 규칙을 추가했다. 기존 차단 규칙보다 높은 우선순위 800으로 조정한 후에만 실제 접근이 가능했다. 실제 주소·프로젝트·호스트·계정은 실행 기록에 넣지 않았다.

모든 GCP 조회에 사용한 임시 OS Login 키는 각 Run 종료 때 제거 명령의 성공을 확인했다. 삭제 명령 성공이 계정의 기존 키까지 포함한 독립적 잔여 0건 검증을 뜻하지는 않는다.

## 다음 검증 관문

1. 승인된 방식으로 Barman의 세 노드 인증을 구성하고 SQL·복제 접속을 확인한다. 비표준 자격증명 파일을 읽어 복제하는 작업은 자동 승인 검토가 거부했으므로 수행하지 않는다.
2. Barman 모델 3개와 Patroni의 영구 물리 슬롯 정책을 점검한다.
3. 감시기를 백업 VM에 설치해 현재 리더에 대한 최초 모델 적용과 WAL 수신 상태를 확인한다.
4. 통제된 리더 변경에서 새 Primary로 수신이 이동하는지, 마지막 WAL부터 새 timeline까지 빠진 파일이 없는지, 격리 복원이 가능한지 별도 Run으로 확인한다.

설계와 운영 조건은 [별도 문서](../../design/barman-wal-follow-primary.md)에 기록했다.
