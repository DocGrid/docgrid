# DR-BARMAN-REPLICATION-20261016-R1 — 세 노드 복제 프로토콜 접속

- 기록 시각: 2026-10-16 21:39 KST. 실행 시작·종료의 초 단위 시각은 수집하지 않았다.
- 목적·위치: GCP 백업 VM의 `barman` 계정에서 현재 `streaming_conninfo`의 인증으로 DB 3노드에 `IDENTIFY_SYSTEM` 요청
- 방법: 기존 인증 파일의 복제 연결 항목을 원격 메모리에서 읽고 `psql`의 `replication=true` 연결에 사용했다. 시스템 ID·WAL 위치·주소·비밀번호는 출력하지 않았다.
- 통과 기준: 3/3 복제 접속, 유효한 응답 3건, 동일 클러스터 ID, 임시 OS Login 키 제거
- 관측: 현재 Primary 1/1 성공, Standby 0/2 성공. 두 Standby 실패는 원문을 버리고 `connection_failed` 범주로만 남겼다. 전체 1/3 성공이므로 동일 클러스터 ID 판정은 불가능하다. 임시 키 제거 명령 성공.
- 판정: **실패**. SQL 인증 3/3 성공과 복제 프로토콜 접근 1/3 성공을 구분한다. 실패 원인은 이 실행만으로 확정할 수 없다.
