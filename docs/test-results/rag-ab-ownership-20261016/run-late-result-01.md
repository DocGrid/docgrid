# 늦은 A 결과 경합 1차 — run-late-result-01

| 항목 | 기록 |
| --- | --- |
| 목적 | A의 모델 응답이 늦고 B가 재선점했을 때 옛 결과가 최종 답변을 덮지 않는지 확인 |
| 시각·위치 | 2026-10-16 05:48:31~05:48:41 KST, 로컬 격리 PostgreSQL·백엔드 JVM A/B·제어 모델 서버 |
| 버전·부하 | `e42651f` 기준 JAR, 합성 RAG 작업 1건, A/B 각각 Worker 동시성 기본값 2 |
| 방법 | A의 첫 모델 응답 보류 → 시험 DB의 A lease·token을 직접 무효화 → B 기동 → 최종 상태 조회 |
| 성공 기준 | B의 완료 결과 1건만 저장, 인용 1건, A의 늦은 완료가 반영되지 않음 |
| 결과 | **불합격·원인 미판정.** 모델 호출 2회, 최종 `FAILED`, 인용 0건. token 변경은 확인됨 |
| 정리 | 시험 행 1건 삭제, A/B와 모델·임베딩 시험 서버 종료 |

```text
05:48:31  A의 첫 모델 요청 보류
05:48:32  A lease·token 시험 무효화 직후 두 번째 모델 요청 수신·응답
05:48:37  B 준비 완료
05:48:40  최종 FAILED · 인용 0건
```

두 번째 모델 요청은 B 준비보다 먼저 관측됐다. A의 여유 Worker 슬롯이 다시 가져갔을 가능성이 있지만 요청을 앱별로 식별하지 않아 발신자를 확정할 수 없다. 따라서 이 실행은 **B가 재선점한 뒤 A의 늦은 결과를 폐기하는 시험으로 판정할 수 없고**, 최종 `FAILED`의 원인도 미판정이다. 실패를 숨기지 않고 남기되 코드 결함이라고 단정하지 않는다. 다음 실행에서는 A 동시성을 1로 제한해 경계를 분리했다.
