# 권한 회수 계측기 로컬 단위 시험 — `ab382-harness-r1`

| 항목 | 기록 |
| --- | --- |
| 목적 | B의 실제 DB 요약을 발행 시각으로 잘못 해석하지 않고, 수신 시각만 가진 결과에 정확한 제한 표시가 붙는지 검증 |
| 위치·시각 | 로컬 작업트리, 2026-10-02 KST |
| 명령 | `python3 -m unittest test_websocket_dashboard_revocation.py -v` |
| 성공 조건 | A/B 할당, STOMP 프레임 분리, 기존 발행시각 분류, 새 `--count-only` 분류가 모두 통과 |
| 관측 결과 | **6/6 통과**, 실패 0, 오류 0. 응답 시각이 먼저 기록됐어도 실제 수신 시각이 그보다 이르면 회수 전으로 분류하는 경계 사례를 추가한 뒤 재실행해 다시 6/6 통과 |
| 해석 | 계측기의 분류 함수가 결정적으로 동작함을 확인했다. 실제 권한 회수 결과는 별도 GCP run의 HTTP 응답과 JSONL 수신 로그로 판정한다 |

`200_후_1초_이내/초과_수신_발행시각미확인`은 네트워크 수신 시각 구분이다. 서버가 언제 권한을 확인했는지 뜻하지 않는다.

GCP 회수 run은 이 경계 사례 보강 전 계측기에서 수행했다. 원본 750개 메시지의 마지막 수신 시각은 HTTP 200보다 약 0.27초 앞서 있어, 해당 run의 회수 후 수신 0건이라는 집계는 이 보강으로 바뀌지 않는다.
