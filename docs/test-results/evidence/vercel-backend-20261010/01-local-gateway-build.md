# 공개 게이트웨이 로컬 빌드·라우팅

- 실행 ID: `vercel-backend-gateway-local-20261010-01`
- 실행 시각: 2026-10-10 KST. 최초 실행의 초 단위 시각은 별도로 보존하지 않았다.
- 위치·대상: 개발 컴퓨터의 Docker, 임시 Nginx 컨테이너. 사설 LB 주소 대신 시험용 미연결 upstream을 사용했다.
- 목적·통과 기준: 이미지 빌드와 `nginx -t` 성공, 공개 진단 경로 응답, 비공개 경로 차단, 시험 컨테이너 종료.
- 명령·절차: `docker build`로 `infra/public-gateway`를 빌드하고, `docker run`으로 임시 실행한 뒤 `nginx -t` 및 `curl`로 경로별 상태를 확인했다.
- 관측: 이미지 빌드와 설정 검사 성공. 당시 로컬 health 경로 204, 보호 경로 404. 연결하지 않은 시험 upstream의 로그인 경로는 예상대로 502였다. 초기 셸 변수 충돌과 샌드박스 네트워크 제한으로 첫 smoke 실행은 완료되지 않았으며, 환경을 바로잡은 재실행에서 위 결과를 얻었다.
- 정리: 임시 Nginx 컨테이너 종료. 로컬 502는 GCP 백엔드 장애의 증거가 아니다.
- 한계: 이 실행은 Cloud Run·내부 LB·실제 백엔드 연결을 검증하지 않는다. 최종 배포에서는 health 경로 이름을 `/__gateway_health`로 변경했다.
