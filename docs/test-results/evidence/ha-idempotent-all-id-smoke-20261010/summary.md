# 전체 ID k6 재전송 — 부하 VM 무장애 스모크 기록

환경: GCP 내부 부하 VM의 k6 2.3.0, 내부 LB를 통한 시험 전용 멱등 HA probe. 실제 VM 장애는 주입하지 않았다. 계정·JWT·내부 주소·프로젝트 식별자는 이 기록에 넣지 않았다.

| 기록 | 목적 | 관측 결과 | 판정 |
| --- | --- | --- | --- |
| [최초 쓰기 r01](initial-r01.md) | 새 ID의 무장애 201·DB 1행 확인 | 10개 ID, 201 10건, 미전송 0, 사전 DB 10행 | 통과 |
| [전체-ID 재전송 r01](replay-r01-failed.md) | 같은 ID를 실제 k6로 재전송 | 스크립트 초기화 오류 107, HTTP 재전송 0건 | 실패·원본 보존 |
| [수정본 루프백 r01](loopback-r01.md) | 수정본을 실제 k6 2.3.0으로 로딩·실행 | 루프백 10회 시도, 원장 20이벤트, 요약 생성, 미전송 0 | k6 실행 경로 통과. 실제 DB 계약은 미검증 |
| [최초 쓰기 r02](initial-r02.md) | 새 ID·새 계정으로 무장애 실제 내부 LB 쓰기 | 201 11건, 미전송 0, DB 각 ID 1행 | 통과 |
| [전체-ID 재전송 r02](replay-r02.md) | 같은 ID·본문으로 실제 k6 재전송 | 200 11건, 201 0, 미전송 0, DB 11→11행·중복 0 | 무장애 소량 계약 통과 |
| [안전 관문 r02](safety-gate-r02.md) | 클러스터·백업·리더 전용 복구 가드 읽기 전용 확인 | 앱·DB·프록시·etcd·스냅샷 확인. ACTIVE 가드 0·IAM 조건 만료 | VM 장애 촬영 NO-GO |

첫 재전송 실패는 숨기지 않는다. 수정 PR 머지·부하 VM 재배포 뒤 새 실행 ID로 201→200 및 DB ID별 1행을 확인했다. **리더 VM 장애 시험은 미실행**이며 독립 복구 가드 미충족으로 보류한다.
