# sync431a02: 비동기 복제 정상 쓰기 측정

- 목적: 동일한 30 req/s·60초 HTTP 쓰기에서 비동기 복제 모드의 지연과 응답·DB 정합성을 확인한다.
- 위치: GCP 내부 부하 VM → 내부 LB → 백엔드 2대 → OpenProxy 2대 → OpenSQL 3노드.
- 시각: 2026-10-04 08:54:23~08:55:25 UTC. 실행 ID: `sync431a02`. 원본 기록은 [실행-기록.txt](실행-기록.txt)에 있다.
- 판정 기준: 미전송 0, HTTP 201 이외 응답 0, 201 요청 ID의 DB 누락·중복 0, 계측 종료 코드 0.

| 확인 | 방법 | 결과 요약 | 해석 |
| --- | --- | --- | --- |
| HTTP 쓰기 | GCP 내부 k6, 30 req/s × 60초, 사전 할당 VU 80 | 1800건; 실패 0건; 미전송 0건 | 정상 쓰기 기준선 통과 |
| 응답 지연 | [k6-summary.json](k6-summary.json) | p50 13.26ms / p95 52.79ms / p99 55.10ms | 이 실행의 분포이며 다른 실행과 합산한 백분위는 아님 |
| DB 대조 | [원장](events.jsonl.gz) → [요청별 DB 행 수](db-counts.csv.gz) → [대조](reconciliation.json) | 201 1800건 = 고유 DB 행 1800건; 누락 0·중복 0·고아 0 | 관측한 성공 응답의 최종 DB 상태가 1:1 |
| 부하 VM | [1초 계측](계측-1초.csv), [계측 요약](계측-요약.json) | CPU 평균 3.1%, 최대 8.5%; 계측 종료 코드 0 | 적어도 부하 발생기 CPU 포화는 관측되지 않음; DB CPU는 측정하지 않음 |

원본 이벤트 시각을 유지해 오프라인으로 가져왔으며, 이 단계는 추가 HTTP 요청을 보내지 않았다. [manifest.json](manifest.json)의 설정 SHA와 실행 기준 커밋, [summary.json](summary.json)의 원장 완료 상태를 확인할 수 있다. 이 정상 기준선만으로 장애 시 RPO 0이나 동기 standby 상실 때의 가용성을 주장하지 않는다.
