# RAG 상태와 알림 대조 — `ws471-r4`

- 목적: 알림이 없는 동안 검색 Job이 끝났는지 독립 HTTP 조회로 확인한다.
- 위치: 로컬 Node → 공개 WSS·HTTP. 2026-10-10 약 05:31 KST.
- 방법: `ws471-r3`와 같은 heartbeat·구독·1초 대기, 검색 응답의 query ID로 90초 뒤 `GET /search/{queryId}`. 본문·JWT·이메일은 기록하지 않는다.

RAG 실패의 하위 원인과 알림 0건의 원인은 아직 확정하지 않았다. 두 백엔드는 Spring SimpleBroker를 각자 보유하며 `RagWebSocketController`의 `convertAndSendToUser`는 현재 Redis 교차 노드 전파를 쓰지 않는다는 코드상 구조가 있다. 이번 관측에서 실제 검색 Worker와 구독 소켓이 서로 다른 앱에 있었는지는 계측하지 않았으므로 원인으로 단정하지 않는다.
