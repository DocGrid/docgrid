# 원복 후 쓰기 smoke — 제한된 증거

| 항목 | 실행·관측 |
| --- | --- |
| 실행 ID·목적 | `sync433post01`; Patroni 비동기 원래 설정과 복제 연결 원복 후 GCP 내부 앱 경로의 정상 쓰기 확인 |
| 방법 | GCP 내부 k6 VM에서 `run_ha_probe_k6.sh sync433post01 30 15s <내부 LB> <보호된 JWT> sync-standby-link-fault 80` |
| 사전 성공 기준 | HTTP 실패·미전송 0, LB 2/2 HEALTHY, DB에 해당 실행의 합성 행 존재 |
| 도구 요약 | runner 종료 코드 0; 451 iterations·451 HTTP 요청·미전송 0·failed rate 0; p50 13.75ms·p95 55.26ms·p99 58.84ms |
| DB 읽기 결과 | 당시 primary에서 `run_id`별 요청 ID 행을 읽기 전용 export: 고유 ID 451개·총 451행(`db-counts.csv.gz`) |
| 판정·한계 | 쓰기 경로는 원복 후 정상. 단, 임시 SSH 키 제거 전 이 실행의 원시 k6 이벤트를 로컬로 복사하지 못했다. 따라서 451 HTTP 결과와 451 DB ID가 요청별로 정확히 대응한다는 **엄격한 원장 대조는 수행하지 않았다**. 클라우드 부하 VM에는 원래 이벤트 파일이 남아 있다 |

이 파일의 HTTP 수치는 실행 당시 runner stdout 및 허용 목록 k6 summary를 조회해 옮긴 값이고, `db-counts.csv.gz`는 별도 읽기 전용 SQL export다. 합성 계정·JWT·임시 SSH 키는 시험 뒤 삭제했고 부하 VM의 기존 실행 디렉터리는 보존했다.
