# #401 공개 비식별 도우미와 실행 중인 세 노드의 일치

- 실행 ID: `issue-401-helper-convergence-01`
- 목적: 공개 코드에 실제 hostname을 하드코딩하지 않으면서 이미 검증한 세 VM의 이미지 ID·PID 1 계약을 같은 도우미로 다시 확인한다.
- 실행 위치: GCP DB VM 3대. 실행 중인 DB 컨테이너는 재시작하지 않는다.
- 절차: 각 VM의 기존 local-only 캡처 이미지에 node-label 태그 추가 → 비식별 도우미를 암호화 SCP로 전송·root 설치 → 로컬/원격 SHA-256 비교 → 기존 컨테이너의 이미지 ID·자원·마운트·PID 1 계약 `verify`.
- 성공 기준: 세 VM 스크립트 해시 3/3 일치, runtime contract 3/3 통과, DB 컨테이너 재시작 0건, 클러스터 leader 1·streaming replica 2·etcd 3/3 유지.
- 첫 실행 결과: 세 VM 모두 비식별 도우미 파일의 SHA-256은 로컬과 일치했다. 그러나 이미지 태그 명령의 원격 셸 변수가 초기화되지 않아 `node: unbound variable`이 **3/3** 발생했고 새 태그를 만들지 못했다. 따라서 새 도우미 `verify`도 Docker 이미지 조회 실패 **3/3**이었다. 외부 셸이 마지막 해시 비교의 성공 코드만 반환해 전체 명령이 0으로 보였으므로 이 실행을 **실패**로 판정한다.
- 안전 상태: 실행 중 DB 컨테이너 재시작 **0건**, Docker 이미지 삭제 **0건**. 이전 태그는 남아 있고 새 도우미는 설치돼 있다. 별도 실행 ID에서 이미지 태그·verify를 명시적으로 다시 수행한다.
