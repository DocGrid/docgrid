# 부하 중 계획 이전 재시험

- 실행 ID: `ha405sw002`
- 목적: 첫 실행에서 실제 승격이 부하 종료 후 일어난 시간 관문 실패를 바로잡는다.
- 위치: GCP 내부 k6 → LB → 앱 A/B → OpenProxy A/B → OpenSQL 3노드.
- 계획: 100 req/s × 180초, 부하가 실제 시작된 것을 확인한 후 node2 primary에서 node1 후보로 계획 switchover. Patroni `history`의 승격 시각이 k6 시작·종료 시각 **사이에 있는지** 확인한다.
- 성공 기준: 승격 전후 충분한 HTTP 표본, 요청별 201/실패/불명 분리, 새 primary에서 201 누락·중복 0건, 최종 leader 1·streaming 2, 시험 계정·타이머 0.
- 관측 시각: k6 2026-10-03 13:50:53~13:53:54 UTC. Patroni `history`에서 기존 timeline 6 종료/새 timeline 7 승격 **13:52:27.228 UTC**. 승격 전 201 **9,186건**, 승격 후 201 **8,352건**으로 부하 창 안에서 실제 역할 이전이 발생했다.
- HTTP: 전송 17,620건 중 201 **17,538건**, 500 **82건**, 결과 불명 **0건**. 첫 500 완료 13:52:25.899 UTC, 마지막 500 완료 13:52:32.048 UTC. 첫 실패 전 마지막 201부터 마지막 실패 후 첫 201까지 **6.279초**(관측된 실패 구간의 경계; 전체 장애의 정확한 RTO 보장은 아님). 최대 연속 201 완료 간격 6.193초.
- 부하 발생기: 목표 18,001개 시간 슬롯 중 **381개 dropped_iterations**, k6 종료 코드 **99**. 기존 `HA_MAX_VUS=160` 상한에서 전환 중 대기 요청이 몰려 일정 유지에 실패했다. p50 10.90 ms, p95 52.22 ms, p99 **1,534.38 ms**. 이 전체 p95는 장애 순간의 지연을 대표하지 않는다.
- 새 primary DB 대조: 201 요청 17,538개가 각각 정확히 1행, 누락 0·중복 0. 500 요청 82개의 DB 반영 0, 고아 행 0. 대조기의 `durable_write_pass=false`, `normal_baseline_pass=false`, 종료 코드 2는 **정상 기준선 전용 통과식이 500·드롭을 허용하지 않기 때문**이며 201 데이터 유실을 뜻하지 않는다.
