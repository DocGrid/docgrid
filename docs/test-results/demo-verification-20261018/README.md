# 예제 시연 판정 회귀 검증

## 목적

예제 인덱싱이 완료됐어도 검색 HTTP 오류·빈 결과·원본 불일치가 있으면 실패 종료해야 한다.
수정 전 잘못된 성공을 재현한 뒤 선택한 범위의 필수 단계로 종료 코드를 결정하도록 수정했다.

## 테스트 환경

- 로컬 Python 3.9.6, 수정 전 `b6ee78bfebfcc8d23b4ee039e2852faf6679fb98`.
- 수정 구현 `775d64f`, 최종 회귀 소스 `defe0ec`.
- 실제 예제 파일 15건(PDF 5·DOCX 5·HWPX 5)을 읽으며 API는 제어 응답으로 대체한다.
- 실제 DB·BGE-M3·Ollama 호출은 0건이다. 실제 모델 E2E나 원격 OpenSQL HA 검증이 아니다.

## 테스트 방법

```bash
python3 -m unittest discover -s scripts/demo -p 'test_*.py' -v
```

1. 수정 전 스크립트에 인덱싱 완료·검색 HTTP 500 또는 빈 결과를 주입한다.
2. 수정 후 같은 오류, 기대 문서 누락·표 본문 누락·파일 불일치·RAG 실패/미완료/잘못된 인용을 검사한다.
3. 정상 search, 제어된 rag 성공, 이전 문서 ID 비교, 기존 원장 보존, 출력 전 마스킹, HTTP 오류 코드와 크기 제한을 확인한다.

실제 모델을 통한 수치가 아니라 제어 응답의 판정 로직 결과다.

## 검증 과정에서 확인된 사항

- 원래 최종 판정은 INDEXED 개수만 보았으며, 검색 함수는 HTTP 오류를 출력하고 반환했다.
- HTTP 오류 본문을 모두 버리면 회원가입 판단에 필요한 USER-004 코드도 사라지므로, bounded 응답에서 코드를 해석하되 임의 메시지는 기록하지 않는다.
- 응답 직후 INDEXED라는 이유만으로 이전 업로드라고 추정하지 않고 이전 실행 문서 ID를 직접 비교한다.
- 로그는 생성 답변·검색 원문을 저장하지 않는다. 마스킹 시험은 비밀값·이메일·URL이 기록 전에 제거됐는지 확인한다.
- 이 회차는 Python 판정 회귀만 실행했다. 새 환경 실제 시연·원격 서비스·생성 모델·DB 내부 Job 수는 미검증이다.
- 원본 개인 환경 파일·기존 Docker 자원·공개 서비스에 변경을 가하지 않았다. 시험 임시 파일은 실행별 임시 디렉터리에서 정리했다.
