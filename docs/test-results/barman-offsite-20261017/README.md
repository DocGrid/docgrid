# Barman 기준 백업·WAL 외부 보존 실행 기록

## 결과

2026-10-17 KST 기준, GCP 시험용 Barman 백업 VM의 완료 기준 백업 1개와 완성 WAL 9개(그중 timeline history 4개)를 **백업 VM 밖의 DB 전용 비공개 GCS 버킷**에 저장했다. Barman export 아카이브 136,919,040바이트의 객체 크기와 CRC32C가 완료 표시의 값과 일치했다. 활성 경로에는 `.partial`·기타 파일이 0개다. 5분 timer의 첫 예약 회차도 정상 종료하고 마지막 성공 시각을 갱신했다.

## 실패 기록과 활성 경로

첫 GCS 전송은 `gsutil rsync -x`가 상대 경로의 **시작부터** 제외식을 매칭한다는 조건을 놓쳐 `.partial` 2개를 함께 복사했다. 제외식을 완성된 WAL·`.backup`·timeline `.history`만 허용하는 형태로 고쳤다. 초기 시험 경로의 객체는 버킷의 **30일 보존 정책 때문에 삭제하지 않았다**. 운영 설정은 새 경로만 가리키며, 복원 시험도 새 경로의 완료 표시와 완성 WAL만 사용해야 한다. 이전 경로를 유효한 백업으로 보고하지 않는다.

## 주장 범위와 다음 관문

- 이번 결과는 **백업 VM 밖의 객체 보존·첫 예약 재실행·오류 감지**를 검증한다. 새 VM에서 GCS 아카이브를 내려받아 `barman import-backup`과 후속 WAL로 시점 복원하는 시험은 아직 하지 않았다.
- Barman의 기준 백업 **생성 주기**는 이번 변경에 포함되지 않는다. 현재 완료 기준 백업 1개의 외부 사본이 확인됐고, 향후 새 기준 백업 생성·전송은 별도로 관측해야 한다.
- 미완성 `.partial`은 보존하지 않는다. 저부하 구간에서 WAL 세그먼트가 닫히지 않으면 5분 timer라도 실제 복구 시점은 더 오래될 수 있다. 성공 응답 원장과 비교한 RPO 보장은 아직 주장하지 않는다.
- 버킷의 현재 객체는 자동으로 만료·삭제하지 않는다. 복원 가능한 새 기준 백업 주기와 보존 정책은 통합 복원 시험 후 정해야 한다. 버킷 보존 기간 30일은 **최소 보존 기간**이며 자동 삭제 기한이 아니다.
- 장기 전송 실패는 5분 주기 health timer가 마지막 성공 시각으로 감시한다. 외부 경보의 수신 채널은 아직 연결하지 않았으며, 실패한 systemd 서비스와 `check`의 비정상 종료를 감시 신호로 제공한다.

설계와 설치·복원 순서는 [Barman 외부 보존 설계](../../design/barman-offsite-preservation.md)에 기록했다. 이 디렉터리의 이벤트 JSONL은 VM 이름·내부 주소·버킷명·계정 정보를 쓰기 전에 제외한 관측값이다.
