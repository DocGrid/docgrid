# 통합 시연 명령의 생명주기 검증

## 목적

시작·검증·종료를 묶으면서 다른 작업의 서버나 개인 환경 파일을 변경하지 않는지 확인한다.
실제 HTTP 자식 프로세스와 포트로 종료 계약을 검사한다.

## 테스트 환경

- 로컬 Python 3.9.6·POSIX·lsof·ps. 최종 구현 `3a17668`, 검사 `3fd9eb7`.
- 임시 작업공간의 제어 HTTP 서버·sleep 자식은 실제 프로세스다.
- Docker 명령·일부 API 상태는 제어 대체물이다. 실제 Docker 기동·DB 연결·BGE-M3 추론은 0회다.
- 공개 서비스와 사용자 실행 자원은 사용하지 않았다.

## 테스트 방법

```bash
python3 -m unittest discover -s scripts/demo -p 'test_*.py' -v
```

전용 프로세스 그룹, 실제 listener 소유권, 자식 종료와 포트 해제, 잘못된 시작 정보의 종료 거부,
부모 상태가 누락된 PID 기록 회수, 동시 명령 거부, 부분 기동 실패 정리, 설정 변경 시 업로드 거부를 확인했다.
개인 환경 파일은 bytes와 수정 시각이 모두 유지되는지 검사했다. 원격 리다이렉트 거부와 여러 줄 비밀값 거부도 포함한다.

HTTP 서버의 수신 프로세스와 그룹을 대조했고, 종료 후 자식 그룹과 실제 수신 포트가 사라졌다.
변경된 PID 식별정보에서는 서버가 계속 살아 있어 자동 종료를 거부함을 확인했다.

## 검증 과정에서 확인된 사항

- PID만 기록하면 재사용된 PID를 오인할 수 있어 시작 시각·명령 fingerprint·그룹을 함께 대조한다.
- 반복 verify는 별도 operation ID를 사용한다. 이전 완료 파일 때문에 다음 실행이 즉시 성공하는 것을 방지한다.
- API 성공만으로 준비를 판정하지 않고 실제 수신 그룹과 관리 포트도 검사한다.
- 원문 비밀번호·JWT·이메일을 제어 자식 출력에 넣어 로그에 남기 전에 마스킹되는지 검사했다.
- 이 검사는 실제 Gradle·프런트엔드·Compose 전체 기동이나 독립 환경의 모델 E2E를 증명하지 않는다.
- 각 검사 임시 프로세스·파일을 정리했다. Native Ollama 실제 기동·종료는 실행하지 않았다.
