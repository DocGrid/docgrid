# OpenSQL 비계획 primary 장애 중 HTTP 쓰기·데이터 보존 측정

실행일: 2026-10-04 KST (원본 시각은 2026-10-03 UTC) · 이슈: [#420](https://github.com/DocGrid/docgrid/issues/420) · 앱 빌드 기준: `160c1ce`

## 결론부터

- **PostgreSQL postmaster만 SIGKILL**한 실행에서는 Patroni가 **같은 노드에서 재시작**했다. 새 리더 선출로 기록하지 않는다. 30 req/s·120초에서 3,601건을 보냈고, 201 응답 3,372건의 DB 누락·중복은 **0건**이었다. HTTP 500은 227건, 결과 불명은 2건이었다.
- **리더 VM을 `--no-graceful-shutdown`으로 중단**한 별도 실행에서는 생존 replica가 새 primary로 승격했고 timeline이 **12→13**이 됐다. 30 req/s·180초에서 5,401건을 보냈고, 201 응답 4,349건의 DB 누락·중복은 **0건**이었다. HTTP 500 467건·503 582건·결과 불명 3건을 숨기지 않는다.
- 두 장애 모두 **결과 불명 중 1건이 DB에 반영**됐다. 결과 불명을 무조건 재시도하면 중복될 수 있으므로 이번 시험에는 자동 재시도를 넣지 않았다. 관측 RPO 0은 **201을 받은 합성 요청 집합에 한정**된다. 비동기 복제 전체의 RPO 0 보장이 아니다.
- 첫 VM 실행의 리더는 OpenProxy A와 같은 VM에 있었다. 따라서 관측된 HTTP 실패는 **primary와 프록시 한 대가 함께 사라진 복합 장애**의 결과다. 순수 DB 단독 VM 장애의 성능 수치로 해석하지 않는다.
- VM 자동 재시작 가드는 실제로 실패했고 운영자가 VM을 직접 재시작했다. 뒤늦은 재시험은 임시 인증의 유효 기간을 넘겨 **전 요청 401**이므로 장애 결과에서 제외했다. 실패 사례는 아래와 실행별 기록에 남겼다.

```text
실제 측정 경로

GCP 내부 k6(합성 request_id, 외부 원장)
    │  HTTP POST, 재시도 없음
    ▼
내부 LB ──────┬──── 앱 A(Hikari) ────┐
             └──── 앱 B(Hikari) ────┤
                                   ▼
                              OpenProxy A/B
                                   │
                     OpenSQL primary + streaming replica 2대
                                   │
                      장애 후 새 primary의 request_id 행 수
                                   │
외부 원장: 201 / 500·503 / 결과 불명 ──┘

실험 1: DB 프로세스만 SIGKILL → 같은 노드 재시작
실험 2: 리더 VM 즉시 중단 → 새 노드 승격 + 옛 노드 replica 재합류
```

## 실패·해석 한계

1. **가용성 실패:** 프로세스 종료에서 500 227건, VM 상실에서 500 467건·503 582건. 원인별 트랜잭션/예외 분석은 별도 [HTTP 500 조사](https://github.com/DocGrid/docgrid/issues/393)로 남긴다. “HA이므로 무중단”이라고 주장할 수 없다.
2. **결과 불명:** 두 유효 장애 실행에서 각각 1건이 실제 DB에 반영됐다. 동일 요청을 자동 재전송하려면 서버 측 `request_id` 멱등성과 응답 계약을 별도로 설계해야 한다.
3. **VM 복구 가드 실패:** 처음에는 백그라운드 가드가 종료됐다. launchd 가드를 다시 띄웠지만 Cloud SDK 환경이 달라 지연 재시작도 실패했다. 운영자가 직접 재시작한 뒤 단일 primary·복제본 2대·etcd 3/3을 확인했다. 실패한 가드는 재사용 코드로 제출하지 않는다.
4. **무효 재시험:** 준비 중 임시 SSH 키·합성 계정·앱 빌드의 유효 기간을 넘어간 뒤 k6가 시작돼 5,401건 모두 401이었다. VM 중단 명령을 실행하지 않았고 DB 반영은 0이다. 정상 또는 장애 성능 표본에 합치지 않는다.
5. **범위:** 10 req/s 정상 관문과 30 req/s 장애 실행은 부하가 다르므로 p95 차이를 장애 효과만으로 설명하지 않는다. 비동기 복제의 장기 RPO, 전체 데이터셋, 재시도 정책, OpenProxy 한 대가 함께 사라지지 않는 순수 DB VM 장애는 이번 결과의 보장 밖이다.

원본 안전 이벤트·1초 계측은 부하 VM의 실행별 폴더와 비공개 로컬 작업 폴더에, DB CSV와 대조 결과는 비공개 로컬 작업 폴더에 보존했다. 저장소에는 반복 가능한 도구와 개인정보·내부 식별자를 제거한 실행별 요약을 싣는다. 원본 검증 SHA-256은 각 실행 기록에 남겨 요약의 출처를 식별한다. 실패한 복구 가드는 [#422](https://github.com/DocGrid/docgrid/issues/422)에서 별도로 고친다.

로컬 코드·원장 검증은 [별도 기록](evidence/issue-420/local-validation-20261004.md)에 남겼다. 전체 애플리케이션 Gradle 회귀 테스트는 이번 실행에서 돌리지 않았으며, GCP 앱 빌드는 `bootJar -x test`로 생성했다.
